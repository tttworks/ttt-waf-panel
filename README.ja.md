# ttt-waf-panel · TTTWorks WAF ファイアウォール・セキュリティ運用パネル

[English](README.md) | [中文](README.zh-CN.md) | **日本語**

> **WordPress サーバー向けの nginx 層 WAF とセキュリティ運用パネル**
> 外部依存ゼロ · 侵入ゼロ · 誤検知なし · **BT パネル（宝塔）対応**

軽量なセキュリティ運用パネルです。nginx 層で正確なブラックリストによる遮断を行い、
すべてのリクエストを「読める・絞れる・追える」パネルに流し込みます。

**重量級の WAF エンジンは不要** —— Docker も Lua も、80/443 を乗っ取るリバースプロキシも要りません。
`map` ディレクティブと少しの PHP、そして少しの Python がスタックのすべてです。

**市販の nginx ファイアウォールを置き換えるために作りました** ——
いくつかの著名なパネルの長所を取り、痛点を避けています（→ [他の選択肢とのトレードオフ](#他の選択肢とのトレードオフ)）。

---

## なぜ作ったか

コンテナ型 WAF には、**小規模なマルチサイトサーバー**で現実的な問題が 3 つあります。

1. **重い** —— 7 コンテナ、数百 MB のメモリ、しかも 80/443 を握ろうとする
2. **誤検知** —— スコアリング型のルールは、しばしば本物の訪問者を締め出す
3. **脆い** —— 内部コンポーネントが壊れると、**サイト全体が遅くなるか落ちる**

実際にあった例：あるサーバーで、WAF の detector socket がカーネルと overlay2 の
マウント伝播の問題で孤立 inode になりました。バックエンドに直接当たると **0.37 秒**、
WAF を経由すると **20 秒** —— 再構築しても再起動しても、バージョンを上げても変わりませんでした。

そこで逆から作りました：**遮断の判断は nginx の中に置く**（`map` は C 実装のハッシュテーブルで、
スクリプトエンジンより速い）、**明らかに悪い通信にだけ手を出し、それ以外は通しつつ記録する。**

## 機能

### 防御層（nginx）

- **正確なブラックリスト** —— 悪意あるユーザーエージェント、悪意あるパス、
  **クエリ文字列インジェクション**（`file_put_contents` / `base64_decode` / `gzinflate` など）。
  スコアではなく文字列一致 → **本物の訪問者を遮断しません**
- **サイト単位の堅牢化** —— `wp-login.php` のレート制限、`uploads/` 配下の PHP 実行禁止、
  `xmlrpc.php` を 403、`/wp-json/wp/v2/users` を 403
- **SEO クローラーの抑制** —— AhrefsBot / meta-externalagent などを固定キーでレート制限。
  通常の利用者は一意キーを使うため、誤検知ゼロ
- **直リンク防止スイッチ** —— サイト単位で画像・メディアに `valid_referers`
- **fail2ban 連携** —— ログイン総当たりの遮断と、jail 状態のパネル表示

### データパイプライン

```
nginx access_log（waf_full 形式、$rule_hit マーカー付き）
   │  cron で 2 分ごとに差分取り込み
   ▼
ingest.py  ← GeoIP 付加（geoip2 + GeoLite2）
   │
   ▼
SQLite（waf.db）  ← 全リクエストとルール命中マーカー
   │
   ▼
api.php  →  index.html（シングルページのフロントエンド）
```

- **差分取り込み** —— ファイルオフセットを記録し、新しい行だけを読みます
- **サイト許可リスト** —— 自分のサイトだけを取り込み、スキャナが偽装したホスト
  （`checkip.amazonaws.com` など）は自動的に捨てます
- **素の IP 接続**はスキップされ、サイト一覧を汚しません

### パネル

| ページ | 内容 |
|---|---|
| **概要** | 総数 / 遮断 / 許可の件数、時間別トレンド、ルール分布、**世界地図**（中国国標準拠の境界線）、上位 20 か国、サーバー指標（負荷 / CPU / メモリ / ディスク） |
| **サイト** | サイトごとのリクエストと遮断、種別判定（WordPress / 静的 / カスタム）、メール構成の検出、直リンク防止スイッチ |
| **地図** | 🌍 世界地図と 🇨🇳 中国地図をワンクリック切替、上位 20 の接続元 IP |
| **リクエスト履歴** | すべてのリクエスト。サイト / ルール / 時刻 / IP で絞り込み |
| **ルール管理** | ユーザールールをオンライン編集、メイン設定は読み取り専用で表示 |
| **最適化ステータス** | OPcache / Memcached / **Redis**（ネイティブ RESP プロトコル、**PHP 拡張不要**）/ BBR / Swap / MySQL を検出・表示し、キャッシュのワンクリック削除に対応。⚠️ **検出と削除のみ —— コンポーネントの導入やチューニングは行いません**（下記参照） |
| **セキュリティ検査** | 総合レポート · リスクスキャン · **悪意あるファイル検出**（ヒューリスティック + ウィルス定義のメタデータ。**検出と特定のみで自動削除は絶対にしません**）· **脆弱性スキャン**（WPScan API）· **サーバー監査**（SSH 設定 / 開放ポート / 未適用の更新 / rootkit 痕跡） |

> ⚠️ **「最適化ステータス」ページについて**：これは**検出と表示のみ**で、加えてキャッシュの
> ワンクリック削除があります。**インストールやチューニングは行いません。**
> OPcache が入っているか・ヒット率はいくつか、Memcached と Redis が動いているか・メモリを
> どれだけ使っているか、BBR が有効か、Swap がどれだけ割り当てられているか、MySQL の主要な
> 設定値は何か —— これらを教えてくれます。
> **しかし、OPcache を代わりに入れたり、`php-fpm` のワーカー数を調整したり、BBR を有効化したり、
> MySQL の設定を書き換えたりはしません。** これらは本番パラメータを直接変更する行為で、
> 間違ったマシンで実行すれば事故です。**何を動かしどこまで踏み込むかはあなたが決めることで、
> パネルは現在の状態を伝えるだけです。**

### エンジニアリング方針

- **外部依存ゼロ** —— ECharts はローカルに同梱、**フロントエンドに CDN リンクなし**
  （Google Fonts も CDN の jQuery もありません）
- **認証** —— `login.php` は bcrypt、Cookie は 7 日、5 回失敗で同一 IP を 15 分ロック、
  ログイン履歴は位置情報付き
- **モバイル対応** —— ブレークポイントは 1024 / 767、ドロワーメニュー、レスポンシブなグラフ
- **導入が簡単** —— `api.php` と `index.html` がそれぞれ 1 ファイル。編集すれば即反映（no-store）
- **リポジトリに機密を含めない** —— パスワードハッシュ、セッション、通信データベース、
  GeoIP データベースはいずれも管理外

## 地図：中国国標に準拠した境界線（本プロジェクトの重要な設計）

> 多くのオープンソースダッシュボード、そしてほぼすべての海外製マップソリューションは、
> 中国の地図を**間違って**描いています —— 南沙諸島の九段線が欠落し、チベット南部がインドに
> 帰属し、台湾が別色で塗られる。こうした地図を中国国内で公開すれば、
> **「地図管理条例」に抵触する可能性があります。**

本プロジェクトの対応：

| 設計 | 内容 |
|---|---|
| **完全ローカル描画** | ECharts（Apache-2.0、同梱）+ ローカル GeoJSON。**オンライン地図サービスを一切呼びません** —— OpenStreetMap も、Google / ArcGIS のタイルも、外部への地図リクエストもありません |
| **世界地図の中国境界は国標準拠** | `lib/world_cn.json` では**中国部分の境界を DataV の公式境界に置き換え**ており、チベット南部・アクサイチン・南シナ海を含みます |
| **九段線を個別に描画** | 世界地図上に**南シナ海の九段線を独立して重ね描き**します —— 中国 GeoJSON の `adcode = 100000_JD` 要素から境界環を取り出し、赤い線で描画。**これは多くのソリューションがまさに省略している部分です** |
| **中国地図モード** | 🌍 世界 / 🇨🇳 中国をワンクリック切替。中国表示では `CN / HK / MO / TW` の接続元のみを集計します |

### コンプライアンス上の注意（必ずお読みください）

- 本プロジェクトが提供するのは**描画コードであり、地図サービスではありません** ——
  タイルを配信せず、地図リクエストを代理せず、**地図データを同梱しません**（データは利用者が取得。→ [`DATA.md`](DATA.md)）
- **海外の地図サービスを一切導入していない**ため、「不適切なベースマップの使用」というリスクを
  構造的に回避しています
- ⚠️ **ただし**：パネルを**公開サービスとして外部に出す**場合、表示される地図の内容については
  現地の法令に照らしてご自身で確認してください（測量資質を持つベースマップサービスの利用、
  または境界データの出所が適法であることの確認など）
- 本プロジェクトは法的助言を構成するものではありません

## 動作環境

| コンポーネント | 要件 | 備考 |
|---|---|---|
| Linux | 主要ディストリビューション | CentOS 7 / 8、Ubuntu 22.04 / 24.04 / 26.04 で稼働実績あり |
| nginx | 1.20+ | BT パネルのビルド版と OS パッケージ版の両方に対応（複数パス検出を内蔵） |
| PHP | 8.x | 必須拡張：`pdo_sqlite`、`mbstring`、`curl`、`json` |
| Python | 3.8+ | `geoip2` モジュールが必要 |
| SQLite | 任意 | PHP の pdo_sqlite で提供 |
| fail2ban | 任意 | 導入されていれば jail 状態を表示。なくても動作します |

> **BT パネル利用の方へ**：BT の nginx には `lua` と `auth_request` が**含まれていません**が、
> 本プロジェクトは**どちらも必要としません**。すべてネイティブの
> `map` / `limit_req` / `internal` で実現しています。

## 他の選択肢とのトレードオフ

> 以下には、**私たちが意図的にやらないと決めたこと**が含まれます ——
> 間違えると本物の利用者を傷つけるからです。

| | **本パネル** | SafeLine（雷池） | BT パネル nginx ファイアウォール |
|---|---|---|---|
| 形態 | nginx ネイティブ `map` + PHP パネル | マルチコンテナ Docker + 80/443 を握るリバースプロキシ | BT パネルのプラグイン（サブスク） |
| 導入コスト | 設定 1 つ + cron 数本 | Docker が必要、メモリ増、ポート占有 | BT パネル内に導入、BT への強い依存 |
| 判定方式 | **正確なブラックリスト**（UA / パス / クエリ文字列） | ルールスコアリング / 意味解析 | ルールライブラリ（比較的不透明） |
| 誤検知 | **ごく稀**（スコアではなく完全一致） | あり（スコア閾値） | あり |
| 追跡可能性 | ✅ 全リクエスト + 個別明細 + ルール命中マーカー | ✅ | 一部のみ |
| 外部依存 | **なし**（Docker / Lua / composer 不要） | Docker | BT パネル |
| パネルへのアクセス | 8089 の独立パネル。ログインして閲覧 | 独立パネル | BT パネル内 |
| 費用 | **オープンソース・無償**（Apache-2.0） | 無償版 + 商用版 | サブスク |

### 意図的に実装していない機能（正直な説明）

- **スコアリングや意味解析はしません** —— 疑わしい通信を取りこぼす方が、本物の利用者を
  遮断するよりましだと考えています。判断できないものは上の層（キャプチャ / スパム対策
  プラグイン）に任せます
- **POST ボディの検査はしません** —— nginx はネイティブにボディを読めません。無理に Lua を
  入れれば依存とオーバーヘッドが増え、正当なフォーム送信を壊しやすくなります
- **人間確認（JS チャレンジ）はしません** —— 追加サービスとフロントエンド改修が必要で、
  効果が見合いません
- **クラウド脅威インテリジェンスはありません** —— ルールは完全にローカルで、読めて、直せます
  （パネル上で編集可能）
- **「全自動インストール」はしません** —— 下記参照

### なぜ Lua やリバースプロキシではなく nginx `map` なのか

- `map` は **C 実装のハッシュテーブル**で、照合コストが非常に低く、新しいエンジンを導入しません
- 遮断の判断が nginx 内に留まるため、**ネットワークホップが増えません**（リバースプロキシ型は
  すべてのリクエストを 1 回余分に転送します）
- BT パネル同梱の nginx には `lua` モジュールが**入っていません**。OpenResty への移行は
  再インストールと全サイトの互換性確認が必要で、コストが利点を上回ります

## 導入にあたって（手を動かせる方向け）

> **これはワンクリック製品ではありません。サーバーを分かっている人向けのツールです。**
> nginx 設定を変更し、cron を追加し、PHP に触ります —— いずれも本番環境では判断力が要る作業です。

**前提**

- nginx の設定が読めて、`nginx -t` を実行できる
- 自分の PHP ソケットパスとログディレクトリを知っている
- いきなり全体ではなく、まず 1 台で試すことを厭わない

**AI アシスタントの利用は問題ありません**

このリポジトリを AI アシスタント（Claude / ChatGPT / WorkBuddy など）に渡し、
自分の環境（BT パネルか OS の nginx か、PHP のバージョン、サイトディレクトリ、ログのパス）を
伝えれば、**実際の構成に合わせた** 3 つの設定と cron を生成してくれます ——
手作業でドキュメントから写すより、たいてい速く、ミスも少なくなります。

`README.md` + `install.sh` + `DATA.md` は、まさにそのために書かれています。
3 つとも AI に渡せば、ほぼ最後まで導いてくれます。

**サポートについて**

本プロジェクトは**無償の導入手順の提供や、導入代行サービスを行いません**。
ここにあるドキュメント、`install.sh` のチェック項目、および以下の FAQ で、
ほとんどの落とし穴はカバーされています。評価した上で、導入を手伝ってほしい場合は
作者までご相談ください。

## クイックスタート（概要）

```bash
# 1) ファイルを配置
mkdir -p /www/wwwroot/wafpanel
cp -r ttt-waf-panel/* /www/wwwroot/wafpanel/

# 2) パネルのパスワードを生成（サーバー上で実行し、ハッシュ内の $ をシェルに展開させない）
php -r 'file_put_contents("/www/wwwroot/wafpanel/panel.passwd", password_hash("your-password", PASSWORD_BCRYPT));'
chown www:www /www/wwwroot/wafpanel/panel.passwd && chmod 600 /www/wwwroot/wafpanel/panel.passwd
#   ↑ 所有者は php-fpm の実行ユーザー：BT パネルは www、Ubuntu 系は www-data

# 3) マシン識別情報
cp server_identity.example.json /www/wwwroot/wafpanel/server_identity.json

# 4) サイト許可リスト（★ 必須。設定しないとパネルは永久に 0 件）
cp ingest.py /www/wwwroot/wafpanel/
vi /www/wwwroot/wafpanel/ingest.py
#   SITES = ('your-site-short-name',)   ← www. を外し、最初のドットより前を取る

# 5) データファイル 2 つをダウンロード（ライセンスの都合で非同梱。DATA.md 参照）

# 6) nginx 設定 —— パネルの vhost、グローバルルール、サイト単位の include
nginx -t && nginx -s reload

# 7) cron（7 本）
```

**動作確認**

```bash
nginx -t
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8089/                          # 200
curl -s -o /dev/null -w '%{http_code}\n' 'http://127.0.0.1:8089/api.php?action=version'  # 200（ログイン不要 — PHP + PDO の健全性確認）
curl -s -o /dev/null -w '%{http_code}\n' -A 'sqlmap' https://your-site/                  # 403
curl -s -o /dev/null -w '%{http_code}\n' https://your-site/xmlrpc.php                    # 403
```

> ⚠️ クラウドサーバーでは、クラウドコンソールのセキュリティグループでパネルのポート
> （既定 8089）も開放してください。BT パネルの導入では UFW / firewalld が自動有効化されるため、
> そちらでも開放が必要です。

## 設定ファイル

| ファイル | 用途 | 注意 |
|---|---|---|
| `panel.passwd` | パネルのパスワード（bcrypt ハッシュ） | **所有者は php-fpm のユーザーである必要があります**。そうでないとログインが常に失敗します |
| `server_identity.json` | マシン識別（`{"no":"server 1","ip":"..."}`） | 未設定なら「ホスト名（IP）」にフォールバック |
| `site_alias.json` | サイト表示エイリアス（ディレクトリ → 公開ドメイン） | 両者が異なる場合に。`site_alias.example.json` をコピー |
| `ingest.py` の `SITES` | **サイト許可リスト** | ★ 新規サイトは必ず追加。でないとデータが捨てられます |
| `waf_rules_user.conf` | ユーザー定義 WAF ルール | パネルのルール管理ページで編集可 |
| `wpscan_token.json` | WPScan API トークン | 脆弱性検査ページで設定 |

## ディレクトリ構成

```
ttt-waf-panel/
├── api.php                  # バックエンド API（単一ファイル。Redis RESP クライアント内蔵）
├── index.html               # シングルページのフロントエンド（ECharts + ローカル GeoJSON 地図）
├── login.php                # ログインページ（bcrypt + Cookie セッション + 総当たり対策）
│
├── ingest.py                # ログ取り込み：waf_full.log → GeoIP → SQLite
├── fail2ban_dump.py         # fail2ban jail / サイト状態 → JSON
├── login_log_geo.py         # ログイン履歴の位置情報解決
├── scan.py                  # 悪意あるファイルのヒューリスティック検査
```

## よくある質問

**ログファイルは増えているのに、パネルのあるサイトが 0 件のまま？**
`ingest.py` の `SITES` 許可リストが間違っています。ホストから `www.` を除き、
最初のドットより前を**完全一致**で照合するため、`example.com` では一致しません。`example` が必要です。

```bash
tail -3000 /www/wwwlogs/waf_full.log | awk -F'|' '{print $3}' | sed 's/"//g; s/^www\.//' | cut -d. -f1 | sort | uniq -c | sort -rn
```

**トップページは開くのに、API がすべて 500 を返す？**
PHP に `pdo_sqlite` 拡張が入っていません。`php -m | grep pdo_sqlite` で確認し、
Ubuntu 系なら `apt install php8.x-sqlite3`。ヒント：`api.php?action=version` は
**ログイン不要**です —— これが 200 なら PHP と PDO は正常です。

**パネルのトップが 403 だが、`/index.html` と `/api.php` は 200？**
vhost の `index` が存在しない `index.php` を指しています（パネルのフロントエンドは静的な HTML）。
次のように変更してください：

```nginx
index index.html;
location / { try_files $uri $uri/ /index.html; }
```

**ある日を境にデータが更新されなくなった？**
ログがローテーションされ、取り込みのオフセット処理が本体ファイル上でしか進まないためです。
本体が 0 バイトで内容が `.1` にあると、何もせず終了します。対処：logrotate を
`copytruncate` にする、またはローテーションをまたいで読み戻せるようにする。

**Redis を入れているのに「未実行」と表示される？**
本プロジェクトは Redis を**ネイティブ RESP プロトコル**で読んでおり、
**PHP の `redis` 拡張に依存しません**。`127.0.0.1:6379` に到達でき、
`requirepass` が設定されていないことを確認してください。

**ログインが常にパスワード誤りになる？**
`panel.passwd` の**所有者**が php-fpm のユーザー（BT パネルは www、Ubuntu 系は www-data）で、
`chmod 600` になっているか確認してください。所有者が root だと php-fpm が読めません。
ハッシュは必ずマシン上で生成します：
`php -r 'file_put_contents("...panel.passwd", password_hash("new", PASSWORD_BCRYPT));'`
—— `$` を含む bcrypt 文字列を `bash -c "..."` に入れてはいけません。シェルが展開します。

## セキュリティについて

- パネルは既定で **8089** を待ち受けます。① クラウドのセキュリティグループで**接続元 IP を制限**し、
  ② 強いパスワードを使ってください
- 業務用エンドポイントは認証が必要です。未ログイン時に `401 {"error":"unauthorized"}` が返るのは
  **正常な動作**です
- `panel.passwd`、`waf.db`、`sessions/`、`GeoLite2-City.mmdb` はすべて `.gitignore` に含まれます ——
  **絶対にコミットしないでください**
- 悪意あるファイルの検査は**ヒューリスティック**です。誤検知・見逃しはあります。
  運用の参考として扱い、唯一の判断材料にはしないでください

## 開発メモ

- バックエンドはフレームワークなし、composer 依存もなし —— 素の PHP と PDO のみ
- フロントエンドはビルド工程なし、バンドラなし —— `index.html` だけ
- 単一ファイルは**導入の最小化**（編集してアップロードするだけ）のための意図的なトレードオフです。
  代償はファイルが長くなることです
- 変更後は必ず：`php -l api.php` → `curl 'api.php?action=version'` → ログイン状態で `action=overview` を確認
